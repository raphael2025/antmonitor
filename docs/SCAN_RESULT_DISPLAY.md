# 扫描结果显示与统计清理

更新日期：2026-11-04。场地端基线 `38e16dc3f4c330241063468aa9aecf4efd117255`。

## 扫描时显示哪一轮

总览、矿机列表、客户、机架及云端上报使用最近一轮完成的扫描结果。新扫描只更新进度，
不会按扫描到的机器数逐步替换总量，也不会因为单台采样超过15分钟而清掉上一轮的显示值。
下一轮完整落库后一次替换。刷新浏览器或服务重启时，从数据库恢复同一份完成结果。
尚未完成首次扫描时显示等待扫描；已完成的空库存是有效的0台，不是尚未扫描。

新一轮实际确认的0算力、离线和读取失败仍照实显示。界面保留上次扫描时间、进度以及真正的失联/
采集停滞提示。这个显示规则不会更新 `measured_ts`；告警和自动重启继续独立核验原始采样新鲜度。

摘要增加 `scan_started_ts`（已完成轮次的开始时间）、`scanning` 和 `scan_progress_ts`。
后者是扫描线程原始进度心跳，不是请求/上报时重新生成的时间。云端据此识别正常推进中的长扫描。

## 趋势和客户统计

场地趋势记录每轮完成结果。新的小时统计使用扫描开始/完成时间：当下一轮按时启动、随后完成时，
上一轮结果可代表该扫描过程中显示的状态；实际采集停止的间隔仍按原15分钟上限截断。
首次完成前的时间不回填。没有开始时间的已有有效历史仍沿用其原始采样限制。
这属于按扫描轮次估算，不是每秒测量或电表读数。

下架是当时的库存变更，保留剩余机器的原采样时间和来源轮次；它不会延长无采集期间的耗电。
尚未由下一完成轮次确定的小时不提前归档，维护任务不会跨过未归档区间删除明细。
新报表只读当前统计模型，不再生成、拼接或回退到旧小时估算。

## 启动时的一次性清理

清理对象是旧 `worker_hourly` 估算，以及缺少完整性字段的旧扫描及其明细。
已经有效的小时统计、当前扫描、设备名册、客户归属、维修标记、告警、命令审计和重启次数保留。

存在待清理内容的文件数据库先写入 `backups/<数据库文件名>.before-statistics-cleanup-v1.db`。
备份成功后，删除和迁移标记在同一事务中提交；失败时不删或整体回滚。重复启动不重复清理或备份。
正常运行不再产生旧小时估算，因此旧统计不会再次出现在报表里。

以下文件不参与清理：`config.yaml`、`segments.json`、`settings.json`、`cloud_site_id.txt`，
以及证书、离线依赖等部署文件。无需手动删除整个数据库。

## 页面呈现

正常报表单元格仅显示数值或 `—`，真实0保留。去除旧口径详情、旧曲线及每格重复的覆盖/迁移说明；
必要的采样或缺测背景放在简短悬停提示中。实际故障、离线、失联和扫描停滞仍可见。
客户CSV也只导出正常统计列和查询时间范围。
