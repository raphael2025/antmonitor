# 矿机运维与功能逻辑审查

审查日期：2026-11-03。场地端基线：`3e8b80ee698885ce3d5e33e3ca2dd8617c15623a`；
配套云端基线：`734e63fa7d2dfee2a05857b7496c2545982048e1`。
本文区分现场用途、可复现程序缺陷和产品策略；不把历史问题清单当作当前缺陷数量。

第 1～5 节记录 2026-11-03 的审查结果；2026-11-04 的后续修复见第 6 节；扫描显示与统计清理见第 7 节。

## 1. 总体判断

现有核心功能适合局域网矿机场地值班：先发现异常，再定位机器、执行处理，最后检查恢复与操作记录。
本轮优先修复会造成重复重启、指令失效、执行记录丢失或错误恢复通知的问题。
没有增加新的首页卡片、表单或操作步骤。

代码审查、临时数据库与模拟设备可以验证软件行为，不能证明所有矿机固件、交换机和水冷控制器都已现场验收。
本轮没有访问生产监控、操作真实矿机、使用上报凭据或实际发送通知。

## 2. 功能是否实用

| 功能 | 运维价值 | 当前能力及边界 |
|---|---|---|
| 名册巡检、全网发现、二次确认 | 核心。新机发现与日常故障检测分开，减少对网络的持续探测压力 | 保留两档扫描；完整扫描不是每次刷新网页。具体速度取决于设备数、响应和配置。 |
| 在线、零算力、低算力、高温、拒绝率告警 | 核心。把“能连上”与“正在正常产出”分开 | unknown 与确认离线分开；整段/全场事件合并，避免把基础设施故障当成数百个独立故障。 |
| IP / SN / 矿工名搜索、离线身份回填、定位灯 | 核心。告警必须能落到实际机器 | 位置视图依赖现场 IP/机位规则；SN/MAC 缺失或重复时不能保证自动识别迁移。 |
| 分批重启、次数限制、冷却、审计 | 核心。执行结果和恢复跟踪比“按钮点成功”重要 | 本次补齐并发、每批复核、中断结果及更新互斥。成功下发不等于机器已恢复算力，仍需后续扫描确认。 |
| 持续零算力自动重启 | 有条件实用。适合明确在线、持续零算力的单机恢复 | 默认关闭；有启动宽限、计时、次数限制和成片事件暂停。它不是温控或冷却故障联锁。 |
| 维修标记、下架移除 | 实用，但名称容易让人误解 | 维修机恢复正算力后自动解除；下架是清理名册，仍通电的机器可能重新被发现。不能代替维护工单、永久退役或资产台账。 |
| AntBox 水温、水压、故障位、独立刷新 | 水冷场地核心；风冷场地按实际设备使用 | 控制器可达和 PLC 数据完整是两件事。缺测保持 unknown，不把没读到故障位当作故障消失。 |
| 当前功率、能效、客户实时/周期算力 | 核心。支持定位低效设备和解释客户产出 | 功率用 kW，电量用 kWh，能效用 J/TH；完整与部分覆盖分别表达。详细口径见 [数据逻辑审计](DATA_LOGIC_AUDIT.md)。 |
| 云端接入与多场地总览 | 多场地核心。场地整场失联时，本地监控不能依靠自己通知 | 同一份 AMC1 包包含地址与凭据，网页和命令界面都可粘贴。云端的失联、骤降和通知可靠性见配套云端审查。 |
| GitHub / Gitee 安装、更新、主题、多语言 | 降低部署和日常使用门槛 | GitHub/Gitee 是代码来源；完全离线仍需预备运行环境和依赖。主题、多语言为便利功能，不应占据故障处理流程。 |
| 换矿池 API、公共 API、开发接口 | 特定运维或集成场景使用 | 当前网页没有普通换池入口；API 仍受权限、二次确认及矿池白名单约束。不能把 API 能力写成已有网页按钮。 |

主要实现依据：`service.py`、`alerts.py`、`control.py`、`db.py`、`server.py`、`web/app.js`、
`data_metrics.py`、`config.example.yaml` 和相应测试。

## 3. 本次复现并修复

### A. 并发请求绕过重启限制

修复前：两个请求在拿重启锁之前都读到旧的限流记录，然后先后拿锁执行。
在最小间隔 900 秒、每天最多 1 次的配置下，同一个 IP 可以在 1 秒内成功下发两次。

修复后：手动和自动都先拿共享重启锁，再查询限流；成功结果在释放锁前写审计。
通知发送位于锁外，不让通知网络延迟阻塞下一次限流检查。

### B. 自动重启排队期间不听从新的状态和设置

修复前：每批 1 台时，第一台完成后关闭自动重启，或把第二台标记为维修，第二台仍会被重启。

修复后：每批真正发送前复核开关、维修/移出名册、当前采样新鲜度、在线且明确零算力、
启动/重启宽限、尝试次数、成片事件暂停与共享限流。未发送的跳过项不计自动尝试，也不设置重启静默。
已下发的那一批无法撤回；改变设置会作用于后续尚未下发的批次。

### C. 批量中断或同组异常丢失执行结果

修复前：后台中断可能只把 running 改为 false，页面显示 0 成功、0 失败。
同组一台机器探测抛异常时，还可能丢掉另一台实际已成功的结果，导致审计缺失和重复重启。

修复后：按设备隔离探测和任务异常，保留已提交任务的结果；后台逐批记录真实进度，
中断时保留成功记录，并区分尚未发送与结果未确认。页面明确显示错误，不把异常当成普通完成。

### D. 命令已发出，但数据库暂时写不进审计

修复前：返回错误后，下一次查询看不到成功记录，可能再次下发。

修复后：当前进程保留原执行时间与待写记录，下一次重启先补记，补记失败时继续拒绝新的重启。
这是进程内保护；数据库不可写且进程同时退出时，不能承诺内存记录仍会保存。

### E. 程序更新开始后插入新的重启任务

修复前：更新仅在开始时检查一次是否正有重启。之后取代码、装依赖、自检期间，新批量重启可以进入，
随后被程序更新的进程退出打断。

修复后：更新持有更新锁再检查重启锁；手动、自动重启持有重启锁再检查更新状态。
无论哪一个先开始，另一方都会推迟；更新响应返回后、进程尚未退出的窗口仍保持保护。
该保护针对同一监控进程中的更新器与重启操作，不能拦截外部管理员直接停止服务或系统断电。

### F. 日志和文档描述与实际行为不一致

旧启动日志仍称弱口令只能本机登录、必须修改后才能操作；实际已有设计是提示修改并保留角色权限。
本次修正文案及安全手册，没有悄悄改变登录权限策略。
同时修正了身份迁移、首次扫描过滤、权限说明；旧 `OPS_ISSUES.md` 标为历史记录，保留原文用于追溯。

## 4. 已知产品边界及建议优先级

这些是需要明确取舍的产品能力，不计作本次已修复的缺陷。

1. **维护窗口与永久退役。** 如果现场需要“只有人确认才恢复”，应设计单独的计划停机/维护锁，
   与当前自动恢复的维修标记分开。下架也应与永久排除扫描分开，避免换了名称却改变旧流程。
2. **自动重启的温控约束。** 当前明确高温的零算力机器仍可能进入自动候选；现有功能没有高温/漏液联锁。
   后续可先对可可靠对应的单机高温增加暂停条件；箱体联动须先确认箱体与矿机映射。
3. **冷却监测本身失效。** 控制器在线但 PLC 字段持续缺失，目前展示 unknown；可考虑单独的持续缺测告警。
   控制器离线超过默认 24 小时会移出当前监控并发提示，也应评估是否改为人工确认移除。
4. **客户边界。** 当前按矿工名归组，不是合同、设备产权或客户独立权限台账。
   云端 viewer 可查看全网，不应作为“只能看自己机器”的客户账号发放。
5. **备份和通知持久化。** 现有数据库热备份工具需要安排执行；通知重试和待写命令审计均有进程内边界。
   多天无人值守场景应单独验收备份恢复、断电重启与外部通知通道。

## 6. 2026-11-04：身份、并发与自动动作可靠性修复

本轮修复基线为 `238c19f34e590c7988148e6fe18a0e9486536a74`，针对复现的完整业务路径追加回归。

- **同 IP 换机。** 两次均有有效 SN 时优先比较 SN；不能可靠比较 SN 时，才使用两次有效 MAC。
  证实换机且尚未读到主矿池客户名时，当前归属记为未知。可靠 MAC 换机还会清除名册中的旧 SN，
  避免旧机器在另一 IP 出现后，新机器被误排除为迁移残影。无效、全零和全 FF 的 MAC 不作身份依据，
  也不覆盖名册已有有效 MAC。旧快照的客户归属保持不变。
- **二次确认的实测零。** 选择顺序为在线正算力、在线实测零、在线缺测、未知、离线。
  每次保留完整获胜样本及其原始采样时间；不把旧字段拼到新时间戳上伪造新鲜度。
- **读库连接维护。** 查询结果在本线程连接锁内取完，维护仅立即关闭空闲连接，活跃连接在查询结束后关闭。
  调用方已经取得的句柄可以重新打开原数据库，已取出的结果可继续读取；线程退出后释放其连接。
  不增加所有读请求共用的全局查询锁。
- **换池、定位与更新互斥。** 所有设备命令共用执行门禁；换池和定位也逐批记录结果。
  更新不能中断正在执行的设备命令，命令也不能插入更新准备或等待进程退出的窗口。
  未落库的执行结果按原执行时间补记，数据库仍不可写时暂停后续命令和更新。
- **自动零算力重启的温度约束。** 候选筛选和每批下发前都要求有效温度严格低于恢复阈值、且无活跃高温告警。
  默认阈值为告警 95℃、恢复 90℃；90～95℃之间也暂停。缺失/无效温度不会被当成已降温。
  未尝试的零算力计时在温度暂停时取消，降温确认后重新等待；已有尝试次数及原执行时间保留。
  自动重启仍默认关闭。单机温度检查不等于 AntBox 漏液、冷却或断电控制联锁。
- **客户报表响应顺序。** 切换周期、同周期再次刷新、离开再进入客户视图时，只渲染当前请求的结果。

回归使用真实文件 SQLite、线程同步、临时扫描序列、模拟设备发送函数和实际前端函数的乱序响应。
专项文件：`tests/test_reader_lifecycle.py`、`tests/test_scan_identity_and_reconfirm_regressions.py`、
`tests/test_auto_reboot_thermal.py`、`tests/test_update_command_gate.py`、`tests/data_quality_behavior.cjs`。

```bash
python -m pytest -q
node tests/data_quality_behavior.cjs
```

本地待写命令审计仍是进程内保护；未落库期间若操作系统同时终止进程，不能承诺该内存记录仍存在。
云端的通知事件与重试状态已另行改为数据库持久化，详见配套云端审查的后续修复章节。

## 7. 2026-11-04：扫描期间保持完成结果，自动清理旧统计

根据实际面板截图复现：上一轮538台在线，其中537台已采样超过15分钟、仅1台较新；
新扫描35%进度时，旧API逐机过期投影把汇总改成1在线、537未知。
现在总览、矿机、客户、机架和上报统一读取最近完成轮次；下一轮完整落库后统一替换。
扫描进度独立显示，刷新网页和进程重启恢复也不依赖浏览器缓存。
真实零、离线和探测失败仍按新一轮结果显示；告警与自动操作保留原始时间和严格新鲜度检查。

每轮保存开始/完成时间，统计可以区分正在正常扫描与采集停止。
新的完成结果覆盖到按时开始的下一轮结束；没有后续采集证据时仍限制延续时间。
库存事件保留原采样轮次来源，不刷新测量时间；尚可能受长扫描影响的小时不提前归档或推进清理水位。

启动时一次性清理不兼容的旧扫描/小时估算；先保存SQLite一致性备份，再事务性删除并记录迁移标记。
配置文件、云端身份、设备名册/客户归属、维修状态、告警和操作记录保留。
报表停止生成和拼接旧估算，网页不再展示旧口径折叠块、旧曲线或重复的迁移说明。
详见 [扫描结果显示与统计清理](SCAN_RESULT_DISPLAY.md)。
