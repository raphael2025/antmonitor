# AntMonitor 两端功能、架构与更新审查

审查日期：2026-11-06。基线：场地端 `f83ee75226f5f5574f674dd6062424d71b33c5c8`；云端 `5752aacab97d9ee7c2588af578ba6f5b015f485e`。

本报告覆盖当前模块、既有回归、更新链路及云端只读页面检查。不会把测试全部通过写成真实矿机、全部固件和生产数据库已验收；没有操作生产矿机、发送测试通知、修改生产设置或部署代码。生产凭据与客户数据不写入仓库。

## 1. 架构判断

两端职责清楚，应继续独立部署。场地端是局域网采集与设备操作的权威来源；云端负责汇总、上报新鲜度和整场失联。SQLite/WAL 适合目前单进程部署，不能直接改成多 worker 后沿用进程内锁、扫描器及通知器。

当前 `server.py` 同时承担路由、授权、配置及数据投影，场地端 `service.py` 同时承担调度、扫描、身份、告警与自动操作。模块继续增长时建议先提取更新生命周期、报表查询和命令协调服务；保留已验证的业务函数，不在一次重构中改统计口径。两端协议与 `update_guard.py` 存在重复，应通过兼容样本和文件一致性检查控制漂移，不要求合并两个仓库。

## 3. 本次可复现缺口与改动

1. **Git 忽略不等于升级保护。** Git 快进可以覆盖被忽略的本机文件。现在检查候选提交树，拒绝跟踪运行配置、数据库、证书、日志/数据目录、配置指定的自定义数据库路径及已有忽略文件。不会因文件名不是默认值而允许接管已配置数据库。
2. **空库检查不能证明旧库能升级。** 两端现在用 SQLite backup API 保存已有库恢复点，在私有临时副本上运行候选版本的真实迁移两次并执行 quick_check。线上库在预演阶段不迁移；新进程启动时再走真实迁移。配置损坏或数据库丢失时停止更新，不拿新空库冒充验证通过。
3. **场地依赖不能在运行环境里尝试安装。** requirements 改变时在 Git 私有目录创建独立 venv，候选编译/导入和迁移均使用该解释器；准备失败删除未使用的候选环境。成功后由已有 server.py/Windows 启动入口选择它，回退使用之前解释器。
4. **更新状态必须在切换代码前可靠保存。** 场地状态改为随机临时文件、fsync 和原子替换；无法持久化时不继续。恢复状态先落盘，进程间文件锁与已有线程锁一起控制网页/CLI 竞争。代码切换后但解释器选择尚未写完时，pending 中的解释器仍可恢复启动。场地端按已验证的固定 SHA 切换，远端引用并发刷新不能偷换候选版本。
5. **自动回退不能覆盖现场修改。** 场地回退检查工作区，使用 reset --keep；HEAD 与待确认版本不匹配时停止回退。健康确认绑定启动版本，旧实例的定时器不能确认刚准备的新版本。
6. **配置读取失败不能重置为默认值。** 场地 settings.json 损坏、根节点异常、已有文件消失时不再作为空配置启动/写回；保存路径也受同一严格读取约束。正常升级不重写 YAML 注释、未知键、JSON 覆盖项、云端身份、矿池或密码。
7. **不能吞掉所有补列错误。** 场地迁移只容忍“列已存在”；锁库、磁盘满和 SQL 错误向上传递，避免带不完整模式运行。
8. **脚本更新不能重建现场服务配置。** 现有服务单元保留，普通更新不重新绑定云端。Git 安装调用受保护更新器；读取服务内联配置环境以核对实际数据库。自定义 EnvironmentFile 部署的脚本更新会明确停止，请使用运行中的网页更新，以免检查错误配置；不擅自解析或改写文件。
9. **源码包也要过滤运行文件。** 两端源码覆盖增加显式排除，保护配置、数据库、WAL、证书、备份、数据目录与运行环境，即使源包意外包含这些内容也不覆盖默认运行文件。自定义路径仍优先采用受保护 Git 更新流程。
10. **在线率取整掩盖掉线。** 云端有掉线时，接近 100% 的值自动提高显示精度；实际 1,999/2,000 显示 99.95%，全部在线仍显示 100.0%。

## 4. 数据迁移与回退边界

- 恢复点是迁移前的完整 SQLite 一致性备份，不包含 YAML/JSON 改写。两端配置在端到端用例中逐字节比对。
- 本次沿用现有迁移规则：不兼容的旧估算统计会按原有一次性迁移清理并保留恢复点；这不表示所有旧统计原样留在当前报表中。名册、身份、有效新统计及操作记录按已有规则保留。
- **不会自动把生产数据库恢复成升级前快照。** 自动覆盖会删除升级后新产生的采样、命令和通知回执。代码/解释器回退与数据恢复是不同动作。未来包含不向后兼容模式变更的版本必须另做兼容性验证或维护窗口迁移。
- Git 更新的预演/回退保护不能追溯保护尚未安装此更新器的旧版本；第一次引入仍由现场旧更新器执行。应先备份并验证旧版到新版的实际升级路径。
- 源码包覆盖、手工 git 操作、容器重建不是同一个更新通道。不要把 Git 用例通过描述成所有部署方式都经过相同回退验收。
- 自定义 systemd EnvironmentFile、启动器参数、无监督服务和全部 Windows 现场组合尚需各自验收；脚本对此拒绝猜测配置，网页更新使用实际运行环境。

## 5. 云端只读检查与仍需现场证据的项目

已查看登录、总览、场地详情、客户表、日报、通知设置和账号安全入口；没有保存设置、发码、删除场地、发测试通知或更新生产程序。

在线率取整已在代码中修正。页面出现当前功率小计但客户/日报电量为空，与当前实现按每个指标完整性独立计算的规则相容，不能据此判定电量计算错误；也不能仅凭云端页面定位哪台机器缺功率或历史是否已丢失。下一步需要本地同一时间窗的原始扫描、固件响应和报表覆盖字段，逐客户核对。不得用当前功率乘 24 小时填补历史。

建议后续优先项：

- P1：把每客户缺功率台数/覆盖原因直接变成诊断证据，核验固件功率字段，解决持续报表空值。
- P1：命令“先落持久化意图、再下发、再记回执”的任务台账，补齐当前进程内待写审计在系统断电时的边界。
- P1：明确永久退役、人工关闭的维护窗口，避免名册清理和自动解除维修造成误解。
- P2：云端采集、报表、通知发送分离为有界任务，防慢 SMTP/Webhook 延后其它告警；健康检查体现后台进度。
- P2：协议增加显式 schema/capabilities 协商和跨版本契约样本，依赖增加经 CI 验证的锁定策略。
- P2：按业务需要引入客户实体、合同归属及租户权限；目前矿工名归组不提供这类保证。
