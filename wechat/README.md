# 微信自动发消息工具 (wechat_send)

控制本机已登录的 **微信(Weixin 4.x)** 客户端,按 **联系人/群名模糊搜索** 并自动发送消息。
纯 Python 标准库实现,**零 pip 安装**,中文 OCR 用 Windows 自带能力,完全离线免费。

> 典型用途:把矿机监控(`E:\ip`)的告警自动推送到指定微信群/人。

---

## 1. 它怎么工作

新版微信 4.x 是 **Qt 重写**的客户端,界面整个画在一块画布上,**对 UIAutomation/wxauto 几乎不可见**(只暴露 2 个元素)。所以本工具不读控件树,而是用「**模拟人操作 + 截图 OCR 看屏**」的方式驱动:

```
找窗口并唤醒(含最小化到托盘的隐藏窗口)
  → 点搜索框 → 剪贴板粘贴名字(微信自带模糊匹配)
  → 截图结果列表 → Windows 中文 OCR 读出每行文字+坐标
  → 智能选中正确目标 → 点击打开聊天
  → 再 OCR 一次顶部标题做二次确认(防发错人)
  → 粘贴消息 + 回车发送
```

两个文件:

| 文件 | 作用 |
|---|---|
| [`wechat_send.py`](wechat_send.py) | 主程序:窗口控制、鼠标/键盘、剪贴板、匹配逻辑、流程(用 `ctypes`,标准库) |
| [`wx_helper.ps1`](wx_helper.ps1) | 「看」的助手:截图 + 调 Windows 自带 `Windows.Media.Ocr` 中文 OCR,返回带绝对屏幕坐标的文字行 JSON |

---

## 2. 运行环境要求

- **Windows 10/11**,且已安装**简体中文 OCR 语言包**(中文系统默认带 `zh-Hans-CN`)。
  自检:`Get-WindowsCapability -Online | ? Name -like "*OCR*Hans*"`,或脚本能跑通即说明可用。
- **微信 Weixin 4.x** 已安装、已登录、保持在**运行**状态(可最小化/托盘,工具会自动唤醒;但不要完全退出)。
- **Python 3.x**(本机用 `py -3.14`)。无需任何第三方库。
- 运行时**不要锁屏**;脚本操作期间会把微信置于前台并模拟鼠标键盘,**请勿同时手动操作鼠标**。

---

## 3. 快速开始

```bash
# 预览(dry-run,默认):会打开聊天窗、做标题确认,但【不发送】
py -3.14 E:\ip\wechat\wechat_send.py --to "云海场地" --msg "矿机#3离线" --type group

# 确认无误后真正发送:加 --send
py -3.14 E:\ip\wechat\wechat_send.py --to "云海场地" --msg "矿机#3离线,请检查" --type group --send

# 发给自己测试(最安全):文件传输助手
py -3.14 E:\ip\wechat\wechat_send.py --to "文件传输助手" --msg "test" --send
```

成功输出示例:
```
[1] 微信窗口: 1669x1075 @ (806,50)
[2] 已搜索: 「云海场地」(模糊)
[3] 命中结果: 「云海场地一二期运维沟通群」 (相似度 0.80)
[4] 聊天标题: 「云海场地一二期运维沟通群(25)」 (与目标相似度 0.62)
[5] 已发送给「云海场地一二期运维沟通群(25)」: 矿机#3离线,请检查

```

## 4. 命令行参数

| 参数 | 必填 | 说明 |
|---|---|---|
| `--to` | 是 | 联系人或群名,**支持模糊**(微信自己模糊匹配 + 本工具 OCR 模糊评分) |
| `--msg` | 是 | 要发送的消息内容(支持中文/任意字符,走剪贴板粘贴) |
| `--type` | 否 | `any`(默认)/ `contact`(只在联系人里找)/ `group`(只在群聊里找)。缩小范围更准 |
| `--send` | 否 | **加上才真正发送**;不加=dry-run 预览,不发任何消息 |
| `--no-confirm-title` | 否 | 跳过「打开后标题二次确认」(**不推荐**,会增加发错人风险) |

退出码:`0`=成功,`2`=失败(未匹配到 / 相似度过低 / 标题确认失败等)。

## 5. 作为模块调用(给矿机监控集成用)

```python
import sys
sys.path.insert(0, r"E:\ip\wechat")
from wechat_send import send_message

res = send_message(
    to="云海场地",          # 目标名(模糊)
    msg="⚠️ 矿机 S19#3 离线",
    kind="group",           # any / contact / group
    send=True,              # False=预览
    confirm_title=True,     # 标题二次确认(建议保持 True)
    verbose=False,          # 不打印过程
)
# res: {"ok": True/False, "target": "...", "msg": "...", ...}
if not res["ok"]:
    print("发送失败:", res.get("reason"))
```

> 集成进 [`alerts.py`](../alerts.py) 时,建议:重要告警 `send=True`,并对 `res["ok"]` 做失败兜底(比如失败时回退到原有通知渠道)。

## 6. 安全机制:为什么不容易发错人

发错人是这类工具最大的风险。本工具有三道闸:

1. **区块过滤**:微信搜索结果分「最常使用/联系人/群聊/聊天记录/聊天文件/功能…」。
   工具只在 `最常使用/联系人/群聊` 里找,**自动跳过「聊天记录」「聊天文件」「功能」**(后者正是会把"文件传输助手"开成特殊弹窗的陷阱)。
2. **长度感知模糊评分**:短名字精确包含 > 长句子里碰巧出现关键词(避免被聊天记录预览句干扰);并跳过「共 N 条相关聊天记录」整块。
3. **标题二次确认**:点开聊天后,**再 OCR 一次顶部标题**(大号字体,识别更可靠),与目标名相似度低于阈值就**中止、不发送**。

> dry-run 模式会完整走到第 3 步并打印将要发送的对象与内容,**就是不按回车**。上线前务必先 dry-run 看一眼。

## 7. 可调参数(布局/时序)

在 [`wechat_send.py`](wechat_send.py) 顶部常量区。**换了屏幕分辨率、微信窗口大小、缩放比例后可能需要微调**:

| 常量 | 含义 | 默认 |
|---|---|---|
| `SEARCH_BOX_DX/DY` | 搜索框点击点(相对窗口左上角) | `160, 55` |
| `RESULTS_DX/W/DY/H` | OCR 结果列文字区(已跳过头像列) | `100/250/78/560` |
| `TITLE_DX/DY/W/H` | 聊天标题 OCR 区 | `345/8/460/44` |
| `CLICK_RESULT_X` | 点结果行时的 X(落在名字上) | `150` |
| `T_AFTER_SEARCH` | 输入后等下拉框出现(秒) | `1.2` |
| `T_AFTER_OPEN` | 点开聊天后等加载(秒) | `1.0` |
| `MATCH_THRESHOLD` | 结果匹配相似度阈值 | `0.45` |
| `TITLE_THRESHOLD` | 标题确认相似度阈值 | `0.45` |
| OCR `-Scale` | 截图放大倍数(小字识别关键) | `3.0` |

## 8. 常见问题排查

- **"未找到微信窗口"**:微信没开/没登录,或被完全退出。最小化、托盘都没关系,工具会唤醒。
- **匹配不到 / 相似度过低**:① 名字太短或太通用 → 用更具体的名字;② 加 `--type` 缩小范围;③ 调大 OCR `-Scale` 或调低 `MATCH_THRESHOLD`;④ 看输出里的 `ocr` 字段是哪些行被读出来,据此调结果区坐标。
- **标题确认失败**:OCR 把标题读偏。可调 `TITLE_DX/W` 对准标题区,或临时 `--no-confirm-title`(不推荐)。
- **点偏了 / 发到搜索框**:多半是窗口大小/分辨率变化导致坐标偏移 → 调 `SEARCH_BOX_*`、`RESULTS_*`、`CLICK_RESULT_X`。
- **中文乱码(控制台)**:`set PYTHONUTF8=1` 或用支持 UTF-8 的终端;不影响实际发送。
- **`.ps1` 报中文解析错**:`wx_helper.ps1` 必须存为 **UTF-8 带 BOM**(PowerShell 5.1 否则按 GBK 读)。若编辑后报错,重存为 UTF-8-BOM 即可。

## 9. 已知限制 & 注意

- 依赖**屏幕坐标 + OCR**,本质上比官方 API 脆:换分辨率/缩放/微信改版可能要重新校准坐标。
- 操作期间会**抢占前台焦点并模拟鼠标键盘**,期间不要手动操作电脑。
- **封号风险**:UI 模拟比协议机器人安全得多(等同你手动点),但**高频群发**仍可能触发风控。建议仅用于**低频告警/通知**,不要刷屏。
- 仅在 **Weixin 4.1.10.31 / Windows 11 / 1669×1075 窗口** 实测过;其他环境首次使用请先 dry-run 校准。

## 10. 设计取舍(为什么这么做)

- 新微信 4.x 是 Qt,免费的 `wxauto` 不支持;付费 `wxautox` 可用但要花钱。本方案用「键盘模拟 + Windows 自带 OCR」做到**免费 + 离线 + 无第三方依赖**。
- 把「看」(截图/OCR,.NET/WinRT 更省事)交给 PowerShell,「控制/逻辑」(窗口/鼠标/键盘/匹配)放在 Python,职责清晰,Python 端零安装。
- 中文输入一律走**剪贴板粘贴**,规避模拟键盘打中文的各种坑。
